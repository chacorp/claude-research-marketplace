---
description: 사용자 요청을 요약하고 구현 계획과 검증 계획을 설계해 승인 후 구현 및 테스트 검증 루프를 수행합니다. $ARGUMENTS에 구현할 내용을 입력하세요.
---

당신은 체계적인 구현-검증 워크플로를 수행하는 에이전트입니다. 아래 단계를 순서대로 엄격히 따르세요.

## 전체 흐름

### STEP 1 — 요청 요약 및 계획 제시

$ARGUMENTS(없으면 최근 대화 맥락)를 바탕으로 다음을 **한 번에** 제시하세요:

```
## 요청 요약
(2~3문장으로 무엇을 만들어야 하는지 핵심만)

## 구현 계획
1. ...
2. ...
(구체적인 파일/함수/변경 단위로 나열)

## 검증 계획
- 테스트 파일: (생성하거나 수정할 테스트 파일 경로)
- 검증 항목: (각 구현 단계별로 무엇을 테스트할지)
- 실행 명령: (테스트 실행 커맨드)

## 최대 검증 루프: N = 3
```

제시 후 **사용자 승인을 기다리세요.** 승인 없이 구현을 시작하지 마세요.

---

### STEP 2 — 구현

사용자가 승인하면 구현 계획에 따라 코드를 작성하세요.
- 계획에 없는 변경은 하지 마세요.
- 구현이 끝나면 "구현 완료. 검증을 시작합니다." 라고 출력하세요.

---

### STEP 3 — 검증 루프 (subagent 위임)

아래 루프를 최대 N=3회 반복합니다. **루프 카운터를 매 회 명시하세요 (예: [검증 1/3]).**

#### 3-1. subagent에게 검증 위임

다음 내용을 포함해 Agent를 호출하세요:
- 역할: "당신은 검증 전담 에이전트입니다. 구현 코드를 직접 수정하지 말고, 오직 테스트 실행과 결과 보고만 하세요."
- 검증 계획에서 정의한 테스트 파일 경로와 실행 명령
- "테스트 결과 전체 출력, 실패 항목 목록, 실패 원인 요약을 반환하세요."

#### 3-2. 결과 판단

- **전부 통과**: "검증 통과. 구현을 완료합니다." 출력 후 루프 종료 → STEP 4로
- **실패 있음**: 실패 원인을 분석하고 코드를 수정한 뒤 다음 루프 반복

#### 3-3. N회 초과 시

N=3회를 모두 소진하고도 통과하지 못하면:

```
## 검증 실패 요약
- 반복 횟수: 3/3
- 미해결 실패 항목: (목록)
- 실패 원인 요약: (간략히)

추가로 N회 더 검증 루프를 진행할까요? (승인 시 횟수를 알려주세요)
```

사용자가 추가 루프를 승인하면 N을 갱신하고 STEP 3을 재개하세요.
사용자가 거부하면 현재 상태를 유지하고 종료합니다.

---

### STEP 4 — 완료 보고

```
## 구현 완료
- 구현 항목: (완료된 작업 요약)
- 검증 결과: 통과 (루프 N회 중 M회에 통과)
- 변경된 파일: (목록)
```
